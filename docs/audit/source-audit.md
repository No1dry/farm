## 产物与复现

- `data/audit/source-manifest.json`：12文件哈希、PDF页数/尺寸、图片尺寸。
- `data/audit/workbook-raw.json`：全部表页及逐行原始值。
- `data/audit/entities.json` / `entities.csv`：100条资料记录和单元格出处；不在此预造业务UUID，由导入后端为稳定来源键首次分配并持久保存UUID。
- `data/audit/area-reconciliation.json`：分区及总计核对、重复表识别、不同口径比较。
- `data/audit/pdf-coverage.json` / `reference-review.json`：逐图覆盖、版本、限制与照片观察。
- `data/audit/pdf-*-page-01.txt`：文本提取中间证据；CAD轮廓字不会完整进入这些文件，不可将搜索无结果解释为图纸没有该实体。

`scripts/audit_sources.py`读取源文件并生成原始提取及预览，`scripts/audit_ledger.py`从原始行重建台账与面积核对。原始源哈希已再次核验；台账100条、来源键100个、面积单位全部null、几何全部null，独立求和1010.99通过。

重建需Python 3.12和Poppler。Python依赖已固定在仓库根目录的 `requirements-audit.txt`；这些工具只读原资料，输出到 `data/audit` 与 `tmp/audit`。从仓库 `farm` 目录执行：

```powershell
python -m venv .venv-audit
& ./.venv-audit/Scripts/python.exe -m pip install -r requirements-audit.txt
$env:POPPLER_BIN = 'C:/tools/poppler/Library/bin'
& ./.venv-audit/Scripts/python.exe scripts/audit_sources.py
& ./.venv-audit/Scripts/python.exe scripts/audit_ledger.py
```

`POPPLER_BIN`接受含pdftoppm的目录或pdftoppm可执行文件路径；若已在系统PATH可省略该变量。查找顺序是显式变量、系统PATH、当前Codex捆绑Poppler；前两种不依赖本机用户缓存。无可用工具或显式路径错误时会明确报错。macOS/Linux使用虚拟环境的 `bin/python`，安装系统Poppler后运行相同两份Python脚本即可。自动重建不会替代视觉核验，`pdf-coverage.json`、`reference-review.json`及本报告包含人工判断，需要资料更新时重新审查。
