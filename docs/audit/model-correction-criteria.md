## 原focus实现的可复用部分与不能照搬的部分

`src/focus/model.js` 已有清晰的立体构成：地面扣除塘和渠的孔洞；水塘侧坡、底面和独立水面；沟渠底部水带及倾斜侧坡；有孔洞的混凝土护坡块；田埂双向缓坡；路肩和碎石路面；几何草叶、残茬和岸石。它们体现的是几何方法和外观语言，应在 Blender 中以新来源轮廓重新构建。

原版 `.42 metersPerPixel`、塘底/水位、沟深、田埂高度、泵房尺寸、电杆布置都是原局部表现设定，不能转化为新资料的测绘事实。原版随机85块远田、42座背景建筑、95块岸石等只能说明曾使用的装饰方法，不能直接复制成为全红线的实际空间对象。

## 全红线场景的构成要求

1. 主场景使用连续地表、明确地物轮廓和独立立体构件。以红线、实际可见湖塘、耕作纹理区、道路、林木覆盖区和聚落覆盖区组织空间。未知的空隙使用连续中性地表，不用随机矩形田块填满。
2. 湖塘必须在连续地表中形成凹槽；水面、岸坡、岸顶至少有三个可见层次。底面与水面不能同高；基础地面不得覆盖水面。中央连续湖泊应保持原来连通轮廓，不能切成独立矩形片。
3. 田块采用浅土埂和材质区分。不能为了“有体积”把每个田块挤成高台、给全部边缘加垂直绿色墙、用厚重边框代替真实田埂。
4. 道路有路面和路肩，沟渠有侧坡和底部。路渠相邻处应有连续衔接；交叉处不得由两个相交的悬浮带材替代实际空间关系。结构未明的交叉点应简化并注明表现关系，不捏造涵管工程结构。
5. 有来源的林地、聚落可以用概略体量组织远景，但它们不能遮盖红线内缺失建模区域。全域远景和近景使用同一套来源轮廓；LOD减少草、石、护坡块等实例，保留水岸、田埂、道路和沟槽形态。
6. 五图仍是独立未配准空间。可以切换到全部图纸的立体片区，但不得为了“全域一张图”把100田块按名字塞入卫星位置。卫星与CAD截图进入资料窗口或默认关闭的对照层，默认主景不得出现图签、印刷文字、网页标注或整页纸框。

## 必须逐项检查的视觉验收

以下均需在最终交付资产和实际浏览器中检查；不能只凭构建完成或自动测试通过打勾。

| 检查项 | 操作与通过条件 | 明确失败现象 |
|---|---|---|
| 主景不依赖截图 | 关闭卫星/CAD对照层并重新载入所有6个空间；仍能识别田、水、路、渠、林地主要空间关系 | 关闭图片后只剩空板、线框或散落薄片；水和田面仍印着源图文字 |
| 真正网格体积 | 临时使用统一不透明灰色材质，从低角度查看：仍能看出塘岸坡、沟槽、田埂和道路路肩；检查网格顶点确有对应高低变化 | 只靠法线图或阴影假象；几何仅一张顶面；加一圈边条便自称有完整立体场景 |
| 湖塘近景 | 沿岸移动视角，水面低于岸顶，岸坡连续落到水下，岸线遮挡随相机变化；地面无盖水、穿水和边缘裂缝 | 水与岸同平面、被基础平面盖住、塘像发光贴纸、倒影或岸线没有空间关系 |
| 沟渠近景 | 从转角及顺渠两个方向查看，能看到两侧坡面、底部/水带、与田面高差；护坡块有受光和遮挡 | 两条彩线或一条圆管代表整条明渠；所有断面在转角互相穿插；块面浮空 |
| 田块近景 | 田面可保持平缓，但田埂应为低矮土坡；边界随原始多边形，残茬仅起近景细节作用 | 地块齐整矩形化、高台化、全部盖同一张航空图；随机作物高度掩盖边界问题 |
| 道路近景 | 路面连续，路肩落地，光照能区分横断面，碎石尺度随镜头自然变化 | 无侧面平带悬浮、纹理像大幅地毯、道路与沟渠重叠抢面 |
| 全域覆盖 | 先看全红线，再检查北/西/东/南及中心湖五处近景；对象和轮廓不是只在一个样板角落存在 | 只做好原来的3田1塘，其余范围靠截图或复制样板掩盖 |
| 五图覆盖 | 每图选一个边界弯折田块、一个可用水/路/渠构件低角度检查；100台账绑定仍保留 | 只给庙下刘立体，其余四图仍是纸面；重建导致田块绑定丢失 |
| 材质与尺度 | 土、草、碎石、混凝土可区分且使用一致的视觉尺度；变换视角后仍自然 | 同一高光材质覆盖所有物体、棋盘重复太强、树草远大于田块、强雾遮盖缺陷 |
| 选择与LOD | 远近切换选中同一业务对象；低LOD仍有岸坡/沟槽/田埂；点选实际可见网格正确反馈 | 高亮另一个对象、靠贴图中文字假选择、LOD切成截图平面、重叠同面对象互抢 |
| 来源与表现分离 | 原始二维轮廓、来源键、UUID和证据不被表现网格改写；三维宽深高独立存为表现参数 | 从显示模型反算台账亩数、把纸面pt称为实测米、把设施文字锚点变成已确认占地 |

建议保存同一最终资产版本的：全域总览、全域低角度岸线、田块近景、沟渠近景、道路近景、五图各一张、关闭对照层截图、灰模截图。每个图片记录资产哈希、视口、相机和视图名称，避免旧截图与新GLB交叉证明。

## 原界面是否保留：独立检查项

以 `deliverables/focus-v02/overview.png` 和 `src/focus/main.js`、`src/focus/style.css` 为对照，在相同1920×1080视口截图比较。原版数据值可以依据全量真实资料更新，布局恢复不能被“数据多了”替代。

- 顶部保留原品牌区、居中标题/副标题、右侧时钟和原资料/全屏入口的层级、尺寸与形状。
- 左侧保留“农田水域单元—地块档案—片区竣工档案”三段分组，右侧保留“环境与水情—灌排工程标注—现场影像资料”三段分组；原照片的地位、比例和浏览操作不被技术状态卡替换。
- 保留原版玻璃卡的边角、透明度、标题条、间距及两侧留给三维场景的中心宽度。不是重新设计一个相近颜色的大屏。
- 原底部四个主要视角按钮及原右侧场景工具条仍有相同位置和层级。全域/分区、搜索、本体、助手等新增能力放入原框架的明确入口或用户打开的抽屉，不用新增固定大块控件挤压默认中心场景。
- 默认视图不打开助手面板遮挡原卡片；资料窗口和照片窗口仍可关闭、键盘返回，并恢复原界面。
- 手机/窄屏沿用原有左右面板抽屉逻辑。不会因为恢复桌面CSS导致列表、档案或关闭按钮不可见。

本轮已经确认的是旧版视觉回归和上述资料支持范围。重建后的布局与立体质量须另行实际查看，不能以本文件作为恢复完成的证明。
