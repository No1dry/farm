## 本轮发现并修复的问题

- 外围重复方塘与地表硬截断：更换为来源湖河和连续简化背景，12:52 Blender 三图独立复核确认。
- 退役设备或不同场景同 key 仍可能显示：图标、模型可见性和点击统一核对 active、dataset、data_nature、scenario、key、parent。
- 入向关系展示方向错误：统一显示数据库完整的主体、谓词和客体，实际 DOM 复核通过。
- 分析“当前演示水塘”时被旧泛名水塘抢占：当前指代使用选中 UUID，明确编号优先、未知编号不退回泛称，保留两字别名和多候选消歧。独立 6 组夹具及实际模型查询复核通过。
- 首次生产浏览器检查发现地表发白、水面发黑，记录保存在 `deliverables/verification/material-export-rejected/`，该批视图不计为视觉通过。地表问题来自旧 MixRGB 节点乘色没有进入 GLB；水面问题来自多个网格反复调暗同一个共享材质。修复与后续实图复验分别记录，不能用 Blender 预览替代网页检查。
- 从保存的多 Scene 源文件重新导出时，其他 Scene 的残留选择可能被带入当前分片：导出限定活动 Scene，并逐片校验空间 ID 集合与清单完全相等；不能只判断所需 ID 是否存在。

## 性能与精度边界

浏览器实测使用 Windows、Chrome、RTX 5070 Ti、1600×1000、DPR 1、本地 HTTP；每个视图结束飞行和资产加载后独立采样 120 帧。最终帧间隔、绘制调用、三角面、加载时间及具体硬件来自 `full-region/review.json`。仅该环境的检查有效，不据此声称手机、低配工控机或外网加载已通过。

本轮 16 视图采样的中位帧间隔约 **6.9–7.0 ms**，P95 约 **7.3–14.2 ms**。当前可见绘制调用和三角面随视角变化；这些是浏览器渲染统计，不是模型全库几何总数。报告中的 assetLoadMs 仅测本地资产请求/解析，不等于外网冷启动时间。保留 Three.js 公共包约 639 kB 的构建提示及 Starlette/httpx 测试客户端弃用警告。

采用全域两级 LOD、片区按需加载及树木 GPU 实例化。精细网格和内嵌材质令资产仍较大；未声称已完成 KTX2、地理瓦片流式传输或所有设备优化。LOD 切换必须保留可选择身份，性能优化不改变来源轮廓。

真实业务资料只有其实际支持的字段：原表面积单位未注；鱼种、密度、设备能力、遥测及生产阈值未提供时，在 real 中仍为空。样例场景具有独立 UUID，固定时间和合成规则不代表现场情况。外观中的楼高、深度、作物行、树种和样例器材也不证明实物存在。

五份竣工图仍在各自纸面坐标中；缺少控制点、正式 CRS、高程基准和可靠照片点位。没有用任意平移或修改边界来凑面积或伪造无缝工程拼接。后续资料更新方式见 `user-guide.md`、`model-methodology.md`、`backend-full-scene.md`。
