# 铜铁海 · 农田与水塘三维原型

面向智慧农业数字孪生系统的第一版空间原型。根据用户提供的卫星截图和总体规划照片，人工描绘红线范围、水系、部分农田与水塘。当前包含 34 块农田、34 块水塘、1 处湖泊，以及田间道路、田埂和植被示意。

## 查看

```sh
npm install
npm run dev -- --port 5173
```

访问 http://127.0.0.1:5173 。浏览器需要支持 WebGL 2。移动端可以通过左上角菜单打开图层、地块索引、台账和建模依据；点击地块详情中的“详情”展开属性。

- 左键拖动旋转，右键拖动平移，滚轮缩放；手机支持触摸操作。
- 点击地块或从索引搜索 F-001 / P-001 等编号，查看属性并定位。
- “卫星核对”显示用户原始卫星截图在同一局部坐标下的底图。
- 农田、水域、田间道路、植被、建筑、标注可分别切换。建筑默认关闭。
- 地块台账支持定位和 JSON 导出；右上角支持独立 GLB 导出。

## 交付文件

- `public/models/tongtiehai-farm-v01.glb`：自包含 glTF 2.0 模型，约 7.6 MB；无需外部纹理或 GPU 实例扩展，保留地块编号和属性。不含背景建筑和网页界面。
- `public/models/parcels.local.json`：地块属性、图像边界、近似局部米制坐标及面积估算。
- `public/references/`：用户提供的原始地图与规划照片，仅供本项目核对，随本地项目保留。
- `src/data.js`：可编辑的地块与线网数据。
- `src/scene.js`：参数化三维模型构建。
- `src/main.js` / `src/style.css`：交互预览与界面。

重新生成模型与地块属性：

```sh
node scripts/export-model.mjs
```

生成无需外部 CDN 的静态站点：

```sh
npm run build
npm run preview
```

`dist/` 通过静态 HTTP 服务即可运行；不要直接用 file:// 打开。所有三维依赖与用户参考图均在本地包内，没有在线地图 API 或服务端账号要求。

## 数据精度与适用边界

本版是待校核的空间示意，不是实景摄影测量、地籍确权或可直接用于工程施工的测绘成果。

- 图像参照尺寸：1952 × 1269。局部原点为图像坐标 (1110, 740)。
- 比例尺根据截图 300 米标尺粗估为 300/101 米/像素，存在读数、影像和描绘误差。
- 模型 X 向图像东侧、Z 向图像南侧，Y 向上。无实测经纬度和地理坐标系配准，不能直接作为 WGS84 GeoJSON 使用。
- 所有亩数均为描绘多边形按近似比例尺计算，并非农场实际台账面积。
- 农田/水塘类型按影像纹理初步判断；未覆盖全部实际地块，不能据 34/34 推断真实数量。
- 地表为平面；底座厚度、田埂、树木、背景建筑及道路宽度为表现参数。无测绘高程、实测水深、真实树木坐标或建筑高度。
- 作物、养殖品种、土壤、水质、气象、灌溉状态与传感器均未接入；未生成模拟实时读数。
- 本版未实现规划项目图层；规划照片作为功能参考保留，未把待建项目当作现状。

## 后续接入

每块农田命名为 `F-xxx`，水塘命名为 `P-xxx`，湖泊为 `L-001`。GLB 节点的 `extras`（Three.js 中为 `userData`）包含 `id`、`kind`、`source`、`verification`、`deviceIds` 等属性。宿主系统可用编号关联业务数据，但设备点位和接口仍需另外提供。

精度提升顺序：校核范围和地块用途 → 替换为 KML/GeoJSON/CAD 边界并完成配准 → 加入 DEM/测绘高程和实测水面 → 关联种养殖台账与设备接口。

三维交互采用 [Three.js OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)，模型导出采用 [GLTFExporter](https://threejs.org/docs/pages/GLTFExporter.html)。
